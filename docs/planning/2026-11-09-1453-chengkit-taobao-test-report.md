## 三、项目定位与用途

### 3.1 解决的问题

淘宝页面为动态渲染，筛选、SKU、购物车勾选等交互全部依赖浏览器内状态，常规爬虫无法稳定获取，官方也没有开放对应接口。本项目通过复用用户已登录的 Chrome 会话，把「人点页面」翻译成结构化的工具调用。

### 3.2 核心能力

- 关键词搜索，并支持页面原生筛选组的读取与组合校验
- 商品详情、评论、图片按任务独立读取
- SKU 组合、面板价、页面库存查询
- 购物车只读读取，含原价、优惠后价、勾选状态与优惠原文
- 授权后仅修改指定行的勾选，或单件加购
- 客服消息读取、草稿准备、确认后发送
- 本机 24 小时选品记录，支持跨对话比较

### 3.3 明确不提供的能力

- 支付、下单、进入结算
- 批量并发采集
- 跨设备或云端共享账号状态

## 四、技术架构

| 层级   | 组成                                   | 职责                 |
| ---- | ------------------------------------ | ------------------ |
| 客户端层 | Trae / Claude Code 等 MCP 客户端         | 发起 JSON-RPC 调用     |
| 服务层  | server.cjs（本地 stdio MCP）             | 工具注册、参数校验、结果封装     |
| 适配层  | tools/ 下的 taobao-\*.cjs              | 页面操作、数据提取、证据标注     |
| 运行时层 | runtime/managed/2.0.2                | 托管 OpenCLI，独立于全局安装 |
| 桥接层  | Browser Bridge 守护进程（127.0.0.1:19825） | 连接终端与 Chrome 标签页   |
| 浏览器层 | 用户真实 Chrome + OpenCLI 扩展             | 提供登录态与实际页面操作       |

关键设计：项目安装自己的运行时和适配器目录（`state/opencli-home/.opencli/clis/taobao`），不修改全局 `.opencli/clis`，因此可与全局 OpenCLI 版本共存。

### 5.3 遇到的问题与处理

问题一：GitHub 直连不可达。

- 现象：`Failed to connect to github.com:443`
- 原因：本机网络对 github.com 的连接被阻断，npm 源与 raw\.githubusercontent.com 正常
- 处理：改用 ghproxy.net 镜像前缀克隆，成功

问题二：绑定脚本首次执行报错。

- 现象：`fetch failed`
- 原因：绑定脚本固定请求 127.0.0.1:19825，而守护进程按需启动、空闲退出，脚本执行时端口无人监听
- 处理：先运行 doctor 拉起守护进程，再执行绑定脚本，一次成功

问题三：换行符导致哈希不一致。

- 现象：初次校验 53 个文件不匹配
- 原因：git core.autocrlf=true，检出时 LF 被转换为 CRLF
- 处理：按原始字节或 LF 归一化双重校验，62 个文件全部通过，确认无内容篡改

## 七、反爬与风控分析

### 7.1 实现方式

项目没有反爬对抗算法，其规避能力来自三点：

- 采用真实 Chrome 与已登录会话，不存在无头浏览器特征
- 操作发生在用户真实标签页，指纹、Cookie、本地存储均为真实值
- 通过节流与停止策略降低触发概率

### 7.2 节流参数

`tools/browser-guard.js` 中定义：

```js
const NORMAL_COOLDOWN_MS = 90_000;
const VERIFICATION_COOLDOWN_MS = 30 * 60_000;
```

- 普通任务间隔约 90 秒
- 页面内动作间隔 10 秒
- 检测到登录或验证码后冷却 30 分钟
- 搜索阶段最多观察 40 次，失败不通过自动刷新掩盖

### 7.3 未实现的对抗手段

检索 tools、templates、taobao-cart 三个目录，未发现：

- User-Agent 伪造
- navigator 属性补丁
- 鼠标轨迹或点击随机化
- 浏览器指纹随机化
- 代理池
- 打码接入

代码中出现的 fingerprint 字段均为本地操作标识，用于防止同一操作换商品或页面重载后沿用旧快照，与反爬无关。

项目文档也明确说明已移除页面伪装注入，且不承诺绕过风控。

### 7.4 效果判断

- 能降低被判定为自动化行为的概率
- 不能保证不被拦截，平台仍可依据账号、IP、行为频率判定
- 被拦截时工具会停止并等待人工处理，不自动重试

## 九、适用建议

### 9.1 适合的场景

- 个人低频、人工主导的购物比价
- 需要 AI 辅助筛选和读取规格的日常购物
- 作为 MCP 与浏览器自动化结合的架构参考

### 9.2 不适合的场景

- 商业产品或对外提供服务
- 大规模批量采集报价
- 无人值守的自动化下单链路

### 9.3 与 PC 配置推荐项目的结合点

- 首期平台已确定为淘宝（Stage 9 决策 Q3=a），本项目可作为首选数据源
- 可借鉴的设计：价格口径分离、证据字段、写入幂等与快照校验
- 不复制其源代码；抓取或解析得到的数据必须标注来源、价格出处与采集时间
- 平台风控与维护成本仍在：只做低频、人工主导的采集，遇阻即停
