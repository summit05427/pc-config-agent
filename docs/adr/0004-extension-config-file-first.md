# 模板扩展配置采用文件优先

Agent 模板需要让接入方新增工具、Agent Profile 与 MCP Server 时不修改核心代码。我们选择以 YAML/目录文件作为扩展事实源，启动期加载并校验，数据库只保存运行时产生的会话级选择。文件可随代码评审、可版本化、可回滚；若一开始就把扩展配置放进数据库，模板会立刻绑定 Admin 与 Java，违背"可裁剪"目标。代价是配置变更需要重启，这一阶段明确不做热加载。

## Consequences

- 新增扩展 = 新增文件，PR 中可见 diff；
- 配置错误在启动期暴露（fail-fast），而不是等到第一个请求；
- 多实例部署时依赖同一份镜像内文件，天然一致；
- 未来数据库化时，文件格式应保持不变，只替换加载来源。
