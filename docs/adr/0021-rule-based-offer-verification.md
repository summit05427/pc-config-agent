# 报价核验改为确定性规则，取消人工逐条核对

## 背景

[ADR 0011](0011-manually-verified-offer-dataset.md) 规定「每条报价必须人工核验，`match_status` 必须为 `VERIFIED` 才能进入推荐」。该决策在只有十几条手工录入报价时成立。

Stage 9 要接入页面采集得到的真实报价，逐条人工核对会成为流程瓶颈，且判定标准只存在于人脑里，无法复现、无法测试、无法在 CI 中回归。若继续保持人工核验作为唯一路径，`OWNER_VERIFIED` 将无人可达，生产求解永远拿不到报价。

## 决策

1. 取消人工逐条核对，改为**确定性规则核验**。规则通过则写 `price_source=OWNER_VERIFIED` 与 `verification_method=RULE`；否则保持 `PLATFORM_OBSERVED`。
2. 核验规则固定为五条：身份一致（MPN 或完整型号 token）、关键规格逐项一致、价格为正整数分且与页面原文一致、必备字段完整、同一硬件只允许一条通过核验的报价。
3. 规则版本写入发布清单；规则必须有单元测试，规则变化等同于数据口径变化。
4. `verification_method=MANUAL` 保留给将来的人工复核，不作为本期路径。
5. 价格分布异常本期只告警不阻断：样本量不足以支撑可信区间，设置阈值等于猜测。

## 考虑过的替代方案

- **保留人工核验**：判定不可复现、不可测试，且无法支撑任何规模的扩展；与「价格必须可追溯」的目标冲突。
- **取消核验，生产直接接受 `PLATFORM_OBSERVED`**：预算在本项目里是硬上限，把套装价、预售定金或错型号价格当成真实成本，会让「预算满足」这个结论失去意义。
- **用大模型做核验**：判定不稳定、不可回归，且无法解释为什么不通过。与 [ADR 0015](0015-lifecycle-unknown-is-not-excluded.md) 的「不猜测」原则冲突。

## 影响

- 本决策取代 [ADR 0011](0011-manually-verified-offer-dataset.md) 的人工核验条款；该 ADR 的其余结论（人民币分、必须有购买链接、无报价不得进入成功方案）继续有效。
- 「核验」的含义从「人确认过」变为「满足一组公开可查的规则」，对外表述不得暗示人工验货。
- 规则过严会让首期 8 款难以全部通过，规则过松会重新引入错误价格；规则阈值调整必须走文档与测试变更，不允许在脚本里临时放宽。
- 核验失败的报价仍然保留为 `PLATFORM_OBSERVED`，可用于排查与展示，但不得进入求解。
